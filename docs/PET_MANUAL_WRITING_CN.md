# 写作与手工点评

本模块不接入 AI，也不会自动发送作文或照片。采用“应用出题 - 独立完成 - 导出材料 - 在聊天中点评 - 保存反馈 - 修改复查”的流程。

## 孩子如何使用

1. 在底部“写作”进入写作本，选择题目并开始新练习。包含三道邮件题、一篇文章题和一道故事题，均为原创练习，不是官方试题。
2. 自己填写审题记录，然后输入作文，或添加最多两张手写照片。照片支持 JPG、PNG、WebP，单张原文件不超过 12 MB，浏览器会在本机压缩图片。保留手机原始照片以便检查笔迹。
3. 填写实际用时、是否独立完成和帮助情况。建议约 100 词、25 分钟，是练习建议；不据此自动评分。
4. 点击“提交并保留原稿”。原稿锁定，后续订正写在修改稿中。未填写文字时，也可以只提交照片；照片不会被自动识别或计字。

## 家长如何交给聊天点评

1. 点击“导出点评材料”，得到 TXT 文件，内含完整题目、审题记录、原稿文字、用时、独立完成情况、已有点评和修改稿。
2. 如果原稿是照片，同时点击每张照片下的“下载照片”，把照片与 TXT 文件一起发到聊天。TXT 文件内不嵌入照片。
3. 收到反馈后，最简单的方式是把点评粘贴到应用的“原稿点评”栏。孩子完成修改后，再次导出同一份材料发到聊天，收到复查反馈后粘贴到“修改稿复查点评”。
4. 若收到点评 JSON 文件，可用“导入点评 JSON”。TXT 材料末尾带有当前作文专属的 JSON 格式；聊天返回代码块时，将其纯 JSON 内容保存为 `.json` 文件再导入。不要包含 Markdown 代码围栏。作文编号或题目编号不一致时会拒绝导入，避免点评放错位置。导入会替换两栏点评，已有点评时会先提示。

示例格式（实际编号必须使用导出材料中的值）：

```json
{
  "kind": "pet-writing-feedback",
  "version": 1,
  "attemptId": "导出材料中的作文编号",
  "taskId": "email-visit",
  "feedback": "优点、要点完成情况、重点错误与修改任务。",
  "revisionFeedback": "没有修改稿时请留空。"
}
```

应用只保存和显示手工点评，不核实点评结论，也不把反馈换算成考试成绩。写作页末尾有完整句子、代词、动名词、地点副词和见面时间地点的六道基础练习，每次核对时显示解释。

## 保存、恢复与限制

- 记录按登录账号保存于浏览器 IndexedDB，最多 12 条。语音与词汇的云同步不包含写作。
- 修改会自动保存；以“已保存到本机”为准。保存失败时先导出备份。多个标签页同时修改时会检测冲突，后写入的一方应先备份，再刷新，避免静默覆盖。
- “导出写作备份（含照片）”保存该账号全部原稿、照片、点评和修改稿，与“我的”页面的词汇备份分开。
- 恢复仅接受相同账号的备份，不覆盖既有内容。完全相同的记录跳过；同编号但内容不同的记录另存为副本，新副本使用新编号，点评前应重新导出材料。
- 移除记录前会触发全部写作记录备份下载，请确认下载文件已保存。用备份可以恢复记录。
- 草稿照片可移除；提交后的照片保留。当前修改稿使用文字输入，纸上修改后需要输入修改稿再导出复查。
- 基础小练习的选项与结果仅保留在当前页面，不加入正式成绩或自动弱项分析。
- 浏览器本机数据不等于加密保险箱，共用设备请使用自己的账号并保留备份。

## 验证范围

单元测试覆盖材料完整性、点评归属校验、备份校验和字数统计。浏览器测试覆盖文字与照片保存、提交后原稿锁定、导入匹配/不匹配点评、修改稿保留、刷新恢复、备份合并、账号隔离，以及桌面和手机布局。
